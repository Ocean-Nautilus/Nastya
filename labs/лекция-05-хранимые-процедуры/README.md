# Лекция 5. Хранимые процедуры — практическая работа

База данных: **Archive_Muzi** (учёт аренды музыкального оборудования), MS SQL Server / SSMS.

## Файлы

| Файл | Назначение |
|---|---|
| `01_создание_процедур.sql` | Создание пяти процедур (`CREATE OR ALTER`) |
| `02_проверка_запусков.sql` | Пункт 7: корректные и ошибочные запуски каждой процедуры |
| `Хранимые процедуры.docx` | Отчёт по работе с местами под скриншоты |

## Процедуры и пункты задания

| Процедура | Пункты задания |
|---|---|
| `usp_ShowAvailableEquipment` | 1 — без параметров |
| `usp_ShowRentalsByClient` | 2 — один параметр `@client_id` |
| `usp_AddClient` | 3 — проверка дубля телефона, 4 — `OUTPUT` с ID клиента, 6 — `TRY...CATCH` |
| `usp_AddPayment` | 5 — аренда должна существовать и сумма > 0, 6 — `TRY...CATCH` + транзакция |
| `usp_CloseRental` | дополнительно — транзакция на две таблицы + `TRY...CATCH` |

## Порядок выполнения в SSMS

1. Выполнить `01_создание_процедур.sql` целиком (F5). В конце скрипт покажет список созданных процедур.
2. Открыть `02_проверка_запусков.sql` и выполнять блоки **по очереди** (выделить блок → F5), а не весь файл сразу — ошибочные запуски специально прерывают пакет.
3. После каждого запуска снимать скриншот вкладок **Results** и **Messages** и вставлять в отчёт на отведённые места.

## Ошибочные запуски: чего ожидать

- `Msg 8144` — процедуре передан лишний параметр;
- `Msg 201` — обязательный параметр не передан;
- `Msg 8114` — вместо числа передан текст;
- `Msg 50000` — сработал `RAISERROR` из собственной проверки внутри процедуры;
- `Msg 8115` — переполнение `DECIMAL(10,2)`; ошибка перехвачена `CATCH`, транзакция откачена.

Примеры вывода в отчёте показаны на жёлтом фоне — это ожидаемый вид сообщений; номера строк
и ID записей у себя будут свои.
