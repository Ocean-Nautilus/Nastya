# Лекция 5. Хранимые процедуры — практическая работа

База данных: **Archive_Muzi** (учёт аренды музыкального оборудования), MS SQL Server / SSMS.

## Файлы

| Файл | Назначение |
|---|---|
| `Хранимые_процедуры.sql` | Весь ход работы: задание → процедура → сразу её проверка |
| `Хранимые процедуры.docx` | Отчёт по работе с местами под скриншоты |

## Как работать в SSMS

Выполнять блоки **по очереди** (выделить блок → F5), а не весь файл сразу — ошибочные
запуски специально прерывают пакет. После каждого запуска снимать скриншот вкладок
**Results** и **Messages** и вставлять в отчёт.

## Структура файла

| Блок | Что делается |
|---|---|
| Задание 1 | `usp_ShowAvailableEquipment` — без параметров → проверки 1.1 и 1.2 |
| Задание 2 | `usp_ShowRentalsByClient` — один параметр → проверки 2.1–2.3 |
| Задание 3 | `usp_AddClient` с проверкой дубля телефона → проверки 3.1 и 3.2 |
| Задание 4 | `CREATE OR ALTER usp_AddClient` + `OUTPUT` с ID и `TRY...CATCH` → проверки 4.1–4.3 |
| Задание 5 | `usp_AddPayment` — аренда должна существовать, сумма > 0 → проверки 5.1–5.3 |
| Задание 6 | `CREATE OR ALTER usp_AddPayment` + транзакция и `TRY...CATCH` → проверки 6.1–6.3 |
| Дополнительно | `usp_CloseRental` — две таблицы в одной транзакции → проверки 7.1–7.3 |

Процедуры создаются через `CREATE OR ALTER`, поэтому файл можно перезапускать:
задания 4 и 6 намеренно дополняют процедуры из заданий 3 и 5.

## Ошибочные запуски: чего ожидать

- `Msg 8144` — процедуре передан лишний параметр;
- `Msg 201` — обязательный параметр не передан;
- `Msg 8114` — вместо числа передан текст;
- `Msg 50000` — сработал `RAISERROR` из собственной проверки внутри процедуры;
- `Msg 8115` — переполнение `DECIMAL(10,2)`; ошибка перехвачена `CATCH`, транзакция откачена.

Примеры вывода в отчёте показаны на жёлтом фоне — это ожидаемый вид сообщений;
номера строк и ID записей у себя будут свои.
